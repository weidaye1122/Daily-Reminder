请帮我开发一个完整的 Docker 化 Web 项目。

项目名称：

日程提醒助手

项目定位：

这是一个用于自定义纪念日、生日、还款日、重要事项等日程提醒的 Web 管理系统。用户可以在网页中添加各种提醒事项，并设置提醒日期、日期类型、提前提醒时间、每天提醒次数、提醒时段，以及通知渠道。系统需要通过 Bark 和企业微信应用消息进行提醒推送。

项目需要支持：

- Docker 部署
- 单用户登录
- 本地化数据存储
- 手机、iPad、桌面端响应式适配
- 公历 / 农历日期
- Bark 推送
- 企业微信应用消息推送

一、核心功能

系统需要支持创建、编辑、删除、启用、停用提醒事项。

每个提醒事项需要包含以下字段：

- 提醒名称
- 日期类型：公历 / 农历
- 日期
- 重复方式
- 提前开始提醒
- 每日提醒次数
- 具体提醒时间点
- 通知渠道
- 备注
- 启用状态

示例提醒事项：

- 结婚纪念日
- 宝宝生日
- 父母结婚纪念日
- 信用卡还款日
- 保险缴费日
- 朋友生日
- 节日提醒
- 自定义事项提醒

二、公历 / 农历日期

创建或编辑提醒时，用户需要可以选择日期类型：

- 公历
- 农历

默认选择：公历。

1. 公历逻辑

如果用户选择公历，则系统按照普通阳历日期计算提醒时间。

例如：

日期：5 月 20 日
日期类型：公历
重复方式：每年

则每年 5 月 20 日触发提醒。

2. 农历逻辑

如果用户选择农历，则系统需要根据每一年的农历日期，自动换算成对应的公历日期后再触发提醒。

例如：

日期：农历八月十五
日期类型：农历
重复方式：每年

则系统每年自动计算当年农历八月十五对应的公历日期，并在对应公历日期触发提醒。

3. 农历日期选择

农历日期选择需要支持：

- 正月、二月、三月、四月、五月、六月、七月、八月、九月、十月、冬月、腊月
- 初一到三十
- 闰月，例如：闰二月、闰六月

需要处理：

- 当前年份不存在对应闰月时，需要提示
- 某个农历月份没有三十日时，需要提示
- 农历换算失败时，需要记录错误日志
- 跨年提前提醒时，需要正确计算

建议使用成熟农历转换库，不要手写复杂历法逻辑。最终以后端计算结果为准，前端只负责展示和交互。

三、重复方式

提醒事项需要支持以下重复方式：

- 每年
- 每月
- 每周
- 一次性

说明：

每年适合生日、纪念日、节日等。
每月适合还款日、缴费日等。
每周适合固定周提醒。
一次性适合只提醒一次的事项。

四、提醒规则

每个提醒事项都可以单独设置提醒规则。

需要支持：

- 当天提醒
- 提前 1 天提醒
- 提前 3 天提醒
- 提前 7 天提醒
- 自定义提前天数

字段示例：

提前开始提醒：7 天前
每日提醒次数：3 次
提醒时间点：09:00、14:00、20:00

含义：

如果某个提醒事项的目标日期是 5 月 20 日，设置提前 7 天开始提醒，则系统从 5 月 13 日开始，每天按照用户设置的提醒时间点推送提醒，直到目标日期当天结束。

如果选择“当天提醒”，则只在目标日期当天按照设置的提醒时间点发送提醒。

如果选择“自定义提前天数”，用户可以手动输入提前天数，例如提前 10 天、20 天、45 天等。

自定义提前天数需要校验：

- 必须是正整数
- 不能小于 0
- 建议最大不超过 365 天
- 输入不合法时需要给出提示

五、每日提醒次数和提醒时间点

用户可以设置每天提醒几次。

例如：

每日提醒次数：3 次

同时需要支持具体提醒时间点：

- 09:00
- 14:00
- 20:00

每日提醒次数应该和提醒时间点数量保持一致。

如果用户修改每日提醒次数，前端需要允许用户增加或减少提醒时间点。

提醒时间点需要校验：

- 时间格式正确
- 同一天内不能重复
- 建议按时间顺序自动排序

二十六、错误处理

需要处理：

- 未登录访问
- 登录过期
- 密码错误
- Bark 配置为空
- Bark 请求失败
- 企业微信配置为空
- 企业微信 token 获取失败
- 企业微信消息发送失败
- 农历日期非法
- 数据库写入失败
- 定时任务异常

所有错误都需要记录到日志中，前端需要给用户友好提示。

二十七、README 文档

README 需要包含：

- 项目介绍
- 功能说明
- Docker 部署方式
- docker-compose 示例
- 环境变量说明
- 默认管理员账号说明
- 修改密码说明
- Bark 配置说明
- 企业微信应用配置说明
- 农历 / 公历说明
- 数据持久化说明
- 数据备份和恢复说明
- 常见问题

二十八、验收标准

项目完成后需要满足：

- 可以通过 Docker Compose 启动
- Web 页面可以正常访问
- 访问后台需要登录
- 默认管理员账号可以登录
- 首次登录后可以修改密码
- 密码加密存储
- 可以新建提醒事项
- 可以编辑提醒事项
- 可以删除提醒事项
- 可以启用 / 停用提醒事项
- 可以选择公历或农历
- 农历日期可以正确换算成公历日期
- 闰月场景有合理处理
- 可以选择当天提醒、提前 1 天、提前 3 天、提前 7 天、自定义提前天数
- 可以设置每天提醒几次
- 可以设置多个提醒时间点
- 可以选择 Bark 和企业微信应用作为通知渠道
- Bark 测试推送成功
- 企业微信应用测试推送成功
- 定时任务可以自动发送提醒
- 不会重复发送同一条提醒
- 消息日志可以查看发送记录
- 手机端可以正常登录、添加提醒、编辑提醒、查看日志
- iPad 端布局正常，不变形
- 桌面端后台布局完整
- 页面没有横向溢出
- 所有数据默认存储在本地 SQLite
- Docker 删除并重建容器后，只要保留 ./data 目录，数据不会丢失
- README 中说明本地数据备份和恢复方式

请按可长期自部署使用的完整项目来实现，不要只做静态页面。优先实现完整功能闭环，再优化 UI 细节。
